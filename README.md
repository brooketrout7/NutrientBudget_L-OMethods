# NutrientBudget_LOMethods

Data and code for a weekly water, nitrogen, and phosphorus budget model for Lake McDonald, Glacier National Park, Montana, USA.

This repository contains the data and R code used to construct the water and nutrient budgets and simulate the effects of wildfire-related nutrient loading.

### `0_data`

Contains the raw data used in the analyses. Files in this directory serve as inputs to the scripts in `1_protocols/`.

### `1_protocols`

Contains the R scripts used to process the raw data, construct the water and nutrient budgets, and run the wildfire simulations.

### `2_incremental`

Contains intermediate files generated by the dependency scripts. These files are subsequently used as inputs to WaterBudget.R and NutrientBudget.R.

Three intermediate files are not included in the GitHub repository because they exceed GitHub's 100 MB file-size limit:

Ft.csv
wildfire_simulation_mass.csv
wildfire_simulation_mass_N.csv

These files are generated locally as part of the analysis workflow and do not need to be downloaded separately.

Specifically:

Ft.csv is generated by:
1_protocols/2_nutrient_budget/dependencies/Tributaries.R
wildfire_simulation_mass.csv and wildfire_simulation_mass_N.csv are generated by:
1_protocols/3_FireSimulation.R

Accordingly, these files will populate 2_incremental/ when the corresponding scripts are run.

The relevant repository structure is:

1_protocols/
│
├── 2_nutrient_budget/
│   ├── dependencies/
│   │   └── Tributaries.R
│   └── NutrientBudget.R
│
└── 3_FireSimulation.R

2_incremental/
├── Ft.csv                         # generated locally; not tracked by Git
├── wildfire_simulation_mass.csv   # generated locally; not tracked by Git
└── wildfire_simulation_mass_N.csv # generated locally; not tracked by Git

Intermediate files in 2_incremental/ can be regenerated from the raw data by running the analysis scripts in the order described below.

Files in this directory should be generated by running the analysis workflow and are not final products.

### `3_products`

Contains the final synchronized water and nutrient budgets generated by the analysis:

* `WaterBudget.csv` — synchronized weekly water budget
* `NutrientBudget.csv` — synchronized weekly nitrogen and phosphorus budgets

## Running the analysis

Scripts should be run in the following order.

### 1. Load required packages

Run:

```text
1_protocols/0_packages.R
```

This script loads the R packages required for the analyses.

### 2. Construct the water budget

Within:

```text
1_protocols/1_water_budget/
```

first run all scripts in the `dependencies/` directory.

These scripts process the raw hydrologic data and populate `2_incremental/` with the intermediate files required by the water-budget model.

After the dependency scripts have been completed, run:

```text
WaterBudget.R
```

The synchronized weekly water budget is written to:

```text
3_products/WaterBudget.csv
```

### 3. Construct the nutrient budget

Within:

```text
1_protocols/2_nutrient_budget/
```

first run all scripts in the `dependencies/` directory.

These scripts process the nutrient-loading and loss data and populate `2_incremental/` with the intermediate files required by the nutrient-budget model.

After the dependency scripts have been completed, run:

```text
NutrientBudget.R
```

The synchronized weekly nutrient budget is written to:

```text
3_products/NutrientBudget.csv
```

### 4. Run wildfire simulations

After the water and nutrient budgets have been constructed, run:

```text
1_protocols/3_FireSimulation.R
```

This script uses the completed budgets to simulate changes in lake nutrient concentrations associated with wildfire-related nutrient loading.

## Workflow

The overall analysis workflow is:

```text
0_data
   │
   ▼
dependency scripts
   │
   ▼
2_incremental
   │
   ├───────────────┐
   ▼               ▼
WaterBudget.R   NutrientBudget.R
   │               │
   ▼               ▼
WaterBudget.csv NutrientBudget.csv
                  │
                  ▼
                3_FireSimulation.R
```

Raw data are therefore retained separately from intermediate files and final products. Intermediate files in `2_incremental/` can be regenerated from the raw data by running the dependency scripts.

## Reproducibility

File paths within the R scripts are constructed using the `here` R package. Analyses should therefore be run from within the repository rather than by changing the working directory to individual folders.

To reproduce the complete analysis, begin with `1_protocols/0_packages.R` and follow the script order described above.
